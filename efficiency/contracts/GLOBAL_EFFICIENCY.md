# AleDevOS P7 — Global Efficiency Contract

P7 is transversal. It governs orchestration, context, skill activation, model/reasoning effort, agent activation, handoffs, tool use and response shape without weakening deterministic gates, security rules, evidence requirements or acceptance criteria.

## Primary invariant

**The user is the goal owner, not AleDevOS's project manager.**

AleDevOS must not ask the user to choose agents, choose skills, coordinate workers, select test order, choose the next operational step, or repeat context already available to the system. User intervention is reserved for product authority, credentials/secrets, irreversible actions and explicit policy exceptions.

## Minimum Necessary Intelligence

For each task, P7 computes an execution profile: `MICRO`, `STANDARD`, `DEEP`, or `CRITICAL`. The profile is deterministic from the Task Contract and explicit signals. It selects the minimum agent/skill/reasoning set that can still satisfy the existing Core gates.

Efficiency never authorizes skipping required Judges, deterministic verification, security constraints, Visual QA when applicable, or required evidence.

## ACTL 1.0

AleDevOS Compact Technical Language is inspired by controlled technical-language principles, not a claim of ASD-STE100 compliance. It uses canonical terms, direct instructions, delta handoffs, reference-by-hash for unchanged evidence and bounded output. Required evidence may exceed output budgets.

## Closed decisions

Classification and routing decisions should use finite choice contracts whenever the answer belongs to a closed set. Free-form prose is not required for `TASK_PROFILE`, `BOOLEAN_NEED`, `ROUTING_ACTION`, or `EFFICIENCY_RESULT`.

## Proof, not vibes

P7 only claims efficiency from comparable baseline/candidate runs. The optimized candidate must preserve final PASS, required gates, judge quality, acceptance criteria, blocker count and repair behavior. Token savings that reduce quality are a FAIL, not an optimization.
