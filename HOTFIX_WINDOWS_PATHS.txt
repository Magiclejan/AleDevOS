AleDevOS v1.51 Final Master Gate — Windows Hotfix 10

Hotfix 1
- Fixed UX/UI Design Context directory detection on Windows.
- Cause: path separator normalization could turn decisions/ into a file named decisions.
- Recovery remains fail-closed for non-placeholder collisions.

Hotfix 2
- Fixed Final Campaign compatibility with Windows PowerShell 5.1 / .NET Framework.
- Cause: scripts P2-P8 and Final Gate used System.IO.Path.GetRelativePath(), which is unavailable in Windows PowerShell 5.1.
- All target runners now use a descendant-only Get-AleDevRelativePath helper built from APIs available in Windows PowerShell 5.1.
- The helper fails closed if an evidence path escapes the AleDevOS package/project root.
- P2 can now record a BLOCKED runtime (for example, an absent OpenCode CLI) and continue to the remaining adapters instead of the campaign aborting on the path API.
- Regression coverage scans every target campaign script and the Windows launcher.
Hotfix 3
- Updated Codex/Claude Code target probe arguments for current CLI compatibility.
- Claude probes use `--permission-mode dontAsk` without requiring newer `--permission-prompts` support.
- Codex approval policy is emitted before the `exec` subcommand in P2/P3/P8 probes.
- P2 runtime checks now default to compact output and preserve full installer/probe details in logs.
- Failed runtime smokes print a short redacted diagnostic instead of only SHA-256 hashes.


Hotfix 4
- Codex P2/P3/P8 target probes use the AleDevOS named permission profiles instead of replacing them with a generic sandbox mode.
- Shell security checks now test protected-scope escape rather than banning ordinary workspace shell execution.

Hotfix 5
- Codex target probes materialize complete permission-profile definitions inline without changing the user's global ~/.codex/config.toml.
- P2 creates its reports directory before redirecting Master Gate console output.

Hotfix 6
- Codex writer permissions use exact AGENTS.md and AGENTS.override.md read paths instead of unsupported readable AGENTS.* globs.

Hotfix 7
- P2 performs runtime CLI discovery before installing a disposable target; missing CLIs are recorded BLOCKED and skipped immediately.
- Windows discovery checks known CLI locations outside PATH, including the official Antigravity %LOCALAPPDATA%\agy\bin\agy.exe location and common OpenCode/Codex locations.
- OpenCode Desktop / Antigravity IDE are reported separately from their required terminal CLIs.
- P2 security probing is deterministic: AleDevOS generates a controlled Node probe and the agent only executes it, so model-authored apply_patch formatting cannot invalidate security evidence.
- Disposable Git targets disable core.autocrlf warnings to keep launcher output concise.


Hotfix 8
- P2 translates BLOCKED states into explicit actions: install/activate CLI, log in, wait/extend quota, or AleDevOS-owned security repair.
- The final runtime summary includes an Action code and an ordered ACCIONES NECESARIAS section.
- P2 prints a single SIGUIENTE PASO RECOMENDADO so the user does not need to interpret raw BLOCKED diagnostics.
- Security-boundary failures are explicitly owned by ALEDEVOS, not delegated to the user as operational coordination.

Hotfix 9
- OpenCode discovery now supports stable `opencode` and beta `opencode2` binaries.
- Windows preflight also checks npm global shims (.cmd/.ps1), Scoop, Chocolatey and common standalone locations.
- If OpenCode exists only inside WSL, P2 reports WSL_ONLY instead of incorrectly claiming it is not installed.
- P2 distinguishes a detected desktop app from a missing automation surface; for Antigravity, the IDE/app is not treated as the `agy` CLI required for deterministic target evidence.
- Missing OpenCode no longer recommends reinstalling blindly; it asks to localize the existing CLI after all known locations are checked.
- P1 self-test count is synchronized with the P1 package certificate to prevent stale-count failures in the full campaign.


Hotfix 10
- OpenCode discovery asks package managers for their actual global bin paths instead of relying only on fixed guesses.
- Added pnpm, Yarn, Bun, Mise, PNPM_HOME, WinGet links, ~/.local/bin, extensionless launchers and running-process recovery.
- Missing runtime diagnostics now describe a discovery failure instead of incorrectly claiming the executable is absent from PATH only.
- OpenCode WSL-only detection remains explicit and does not masquerade as a native Windows CLI.
